# Repository Classification Standard

> [!abstract]
> Настоящий стандарт определяет систему классификации репозиториев организации Sun Decor.
>
> Стандарт устанавливает допустимые типы репозиториев, их назначение и принципы использования.
>
> Цель стандарта — обеспечить единообразную организацию инженерной платформы GitHub и исключить неоднозначность назначения репозиториев.

---

# Purpose

Стандарт существует для определения единой модели классификации репозиториев организации.

Он позволяет:

- определить назначение каждого репозитория;
- исключить смешение различных типов содержимого;
- обеспечить единообразную структуру инженерной платформы;
- упростить сопровождение организации GitHub;
- создать основу для последующих стандартов, описывающих требования к каждому классу репозиториев.

---

# Scope

Настоящий стандарт распространяется на все репозитории организации Sun Decor.

Стандарт обязателен как для существующих, так и для вновь создаваемых репозиториев.

---

# Repository Classification Model

Каждый репозиторий организации относится **ровно к одному** классу.

```text
Repository
│
├── Product
├── Documentation
├── Infrastructure
├── Template
└── Archive
```

Класс репозитория определяется его основным назначением.

Использование нескольких классов одновременно не допускается.

---

# Repository Classes

## Product

Репозиторий, содержащий исходные материалы отдельного продукта.

Как правило, включает:

- исходный код;
- документацию продукта;
- конфигурацию;
- ресурсы продукта;
- систему управления разработкой.

Каждый продукт организации размещается в собственном репозитории.

---

## Documentation

Репозиторий, предназначенный исключительно для хранения документации.

Документация может относиться:

- к организации;
- инженерной платформе;
- архитектуре;
- процессам;
- отдельным продуктам.

Примером такого репозитория является **knowledge-base**.

---

## Infrastructure

Репозиторий, содержащий инфраструктурные компоненты организации.

Например:

- `.github`;
- общие GitHub Actions;
- шаблоны GitHub;
- инфраструктурные конфигурации;
- инструменты автоматизации.

Инфраструктурный репозиторий не содержит материалы отдельных продуктов.

---

## Template

Репозиторий, предназначенный для повторного использования в качестве шаблона.

Шаблон может использоваться при создании новых продуктов, сервисов или иных инженерных артефактов.

---

## Archive

Репозиторий, выведенный из активной эксплуатации.

Архивные репозитории сохраняются исключительно для исторической прослеживаемости.

Разработка в архивных репозиториях не ведётся.

---

# Classification Rules

> [!important]
> Требования данного раздела являются обязательными.

## Rule 1 — Single Classification

Каждый репозиторий обязан принадлежать ровно одному классу.

---

## Rule 2 — Stable Classification

После создания репозитория его класс не должен изменяться без объективной необходимости.

Изменение класса допускается только при существенном изменении назначения репозитория.

---

## Rule 3 — Purpose Driven

Класс определяется назначением репозитория, а не его содержимым.

---

## Rule 4 — One Product — One Repository

Для каждого самостоятельного продукта создаётся отдельный репозиторий.

Настоящее правило определяется архитектурным решением [[ADR-0016]].

---

## Rule 5 — Separation of Concerns

Материалы различных классов не должны смешиваться в одном репозитории.

Например:

- инженерные стандарты не размещаются в продуктовом репозитории;
- исходный код продукта не размещается в репозитории документации;
- инфраструктурные настройки организации не размещаются внутри продукта.

---

# Recommendations

Рекомендуется:

- определять класс репозитория до его создания;
- придерживаться минимального количества репозиториев;
- создавать новый репозиторий только при наличии самостоятельной ответственности;
- использовать существующие репозитории, если новое содержимое соответствует их назначению;
- регулярно пересматривать структуру организации на предмет дублирования.

---

# Exceptions

Исключения допускаются только при наличии документированного архитектурного решения.

---

# Rationale

Классификация репозиториев является фундаментом инженерной платформы GitHub.

Она позволяет:

- определить ответственность каждого репозитория;
- избежать дублирования информации;
- обеспечить единообразие инженерной системы;
- упростить навигацию;
- создать основу для автоматизации управления организацией.

Использование единой модели классификации обеспечивает масштабируемость инженерной платформы по мере роста количества продуктов и репозиториев.

---

# Compliance

Стандарт считается соблюдённым, если:

- репозиторий относится к одному из утверждённых классов;
- класс соответствует фактическому назначению репозитория;
- материалы не смешиваются с другими классами;
- соблюдается принцип One Product — One Repository;
- исключения документированы.
