# Project Standard

> [!abstract]
> Настоящий стандарт определяет правила использования GitHub Projects в инженерной платформе Sun Decor.
>
> Стандарт устанавливает назначение Projects, требования к их структуре и место в инженерном процессе.
>
> Цель стандарта — обеспечить единообразное управление инженерной работой и реализацию утверждённого Engineering Workflow.

---

# Purpose

Стандарт существует для определения единых правил использования GitHub Projects.

Он позволяет:

- организовать управление инженерной работой;
- обеспечить единый жизненный цикл задач;
- визуализировать состояние разработки;
- централизовать планирование;
- создать основу для автоматизации инженерного процесса.

---

# Scope

Настоящий стандарт распространяется на все GitHub Projects организации Sun Decor.

---

# Project Lifecycle

GitHub Project является системой управления инженерным процессом.

Типичный поток работы выглядит следующим образом:

```text
Issue
    │
    ▼
Project
    │
    ▼
Workflow
    │
    ▼
Completion
```

Изменение состояния работы осуществляется посредством утверждённого Engineering Workflow.

---

# Usage Principles

GitHub Project используется исключительно для управления инженерной работой.

Project:

- объединяет связанные Issues;
- реализует утверждённый Workflow;
- отражает текущее состояние разработки;
- не заменяет документацию;
- не используется для хранения инженерных решений.

---

# Project Rules

> [!important]
> Требования данного раздела являются обязательными.

## Rule 1 — Single Source of Workflow

GitHub Project является единственным источником информации о текущем состоянии инженерной работы.

---

## Rule 2 — Workflow Compliance

Каждый Project обязан использовать утверждённый Engineering Workflow.

Самовольное изменение этапов Workflow не допускается.

---

## Rule 3 — Issue-Based Management

Управление работой осуществляется исключительно посредством GitHub Issues.

Project не содержит самостоятельных рабочих элементов.

---

## Rule 4 — Workflow Status

Состояние инженерной работы определяется исключительно положением Issue в Workflow.

Закрытие Issue не заменяет прохождение этапов Workflow.

---

## Rule 5 — Transparency

Текущее состояние Project должно отражать фактическое состояние инженерной работы.

---

## Rule 6 — Consistency

Все Projects организации должны использовать единые инженерные принципы управления работой.

Допускаются только документированные различия, обусловленные особенностями конкретного продукта.

---

# Recommendations

Рекомендуется:

- использовать единый шаблон Workflow;
- регулярно актуализировать состояние Issues;
- минимизировать количество пользовательских полей;
- автоматизировать изменение статусов при возможности;
- использовать Projects как основной инструмент ежедневного управления разработкой.

---

# Exceptions

Исключения допускаются только при наличии документированного архитектурного решения.

---

# Rationale

GitHub Project является центральным элементом инженерного процесса Sun Decor.

Использование единых правил позволяет:

- обеспечить прозрачность разработки;
- унифицировать управление задачами;
- повысить предсказуемость процесса;
- подготовить инженерную платформу к автоматизации;
- обеспечить единый подход ко всем продуктам организации.

Project объединяет отдельные инженерные задачи в управляемый процесс и обеспечивает реализацию Engineering Workflow.

---

# Compliance

Стандарт считается соблюдённым, если:

- Project используется для управления инженерной работой;
- все рабочие элементы представлены GitHub Issues;
- применяется утверждённый Workflow;
- состояние Project соответствует фактическому состоянию разработки;
- отсутствуют необоснованные отклонения от настоящего стандарта.
