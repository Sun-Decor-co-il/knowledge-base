# Label Standard

> [!abstract]
> Настоящий стандарт определяет правила использования GitHub Labels в инженерной платформе Sun Decor.
>
> Стандарт устанавливает назначение Labels, принципы их применения и требования к классификации инженерных артефактов.
>
> Цель стандарта — обеспечить единообразную классификацию инженерной работы и создать основу для автоматизации процессов разработки.

---

# Purpose

Стандарт существует для определения единых правил использования GitHub Labels.

Он позволяет:

- классифицировать инженерные артефакты;
- повысить прозрачность инженерного процесса;
- обеспечить единый язык классификации;
- упростить поиск и фильтрацию;
- создать основу для автоматизации инженерной платформы.

---

# Scope

Настоящий стандарт распространяется на все GitHub Labels организации Sun Decor.

---

# Label Concept

GitHub Label представляет собой классификационный признак инженерного артефакта.

Label описывает свойства объекта, но не изменяет его поведение.

Labels могут использоваться для классификации:

- Issues;
- Pull Requests;
- Discussions.

---

# Usage Principles

GitHub Labels используются исключительно для классификации инженерных артефактов.

Labels:

- не определяют Workflow;
- не заменяют Milestones;
- не заменяют GitHub Projects;
- не используются для хранения информации, которая имеет собственную доменную сущность.

---

# Label Rules

> [!important]
> Требования данного раздела являются обязательными.

## Rule 1 — Classification Only

Каждый Label должен описывать один классификационный признак.

Label не должен использоваться для передачи нескольких независимых смыслов одновременно.

---

## Rule 2 — Standardized Vocabulary

Используется только утверждённый набор Labels.

Создание произвольных Labels не допускается.

---

## Rule 3 — Single Responsibility

Каждый Label относится только к одной категории классификации.

Например:

- Type
- Priority
- Status
- Area

Смешение различных категорий в одном Label не допускается.

---

## Rule 4 — Reusability

Labels должны быть универсальными и пригодными для повторного использования.

Не допускается создание Labels под конкретную задачу или продукт без документированного обоснования.

---

## Rule 5 — Consistency

Labels одной категории должны использовать единые правила именования, оформления и применения.

---

## Rule 6 — Automation Compatibility

Labels должны быть пригодны для автоматической обработки средствами GitHub Actions и других инструментов инженерной платформы.

---

# Label Categories

Настоящий стандарт определяет использование категорий Labels.

Конкретный перечень категорий и Labels определяется специализированными стандартами.

---

# Recommendations

Рекомендуется:

- использовать минимально необходимое количество Labels;
- избегать дублирующих классификаций;
- регулярно пересматривать набор Labels;
- использовать Labels как единый источник классификации инженерных артефактов;
- проектировать Labels с учётом будущей автоматизации.

---

# Exceptions

Исключения допускаются только при наличии документированного архитектурного решения.

---

# Rationale

GitHub Labels являются универсальным механизмом классификации инженерной работы.

Использование единых правил позволяет:

- обеспечить единообразие инженерной терминологии;
- повысить качество фильтрации;
- упростить построение отчётов;
- подготовить инженерную платформу к автоматизации;
- обеспечить масштабируемость инженерного процесса.

Labels рассматриваются как элемент инженерной модели данных, а не как средство визуального оформления.

---

# Compliance

Стандарт считается соблюдённым, если:

- Label относится к одной категории;
- используется утверждённая терминология;
- отсутствуют дублирующие Labels;
- классификация выполняется единообразно;
- Labels пригодны для автоматической обработки.
