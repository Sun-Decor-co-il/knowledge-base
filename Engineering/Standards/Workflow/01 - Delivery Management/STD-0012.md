# Milestone Standard

> [!abstract]
> Настоящий стандарт определяет правила использования GitHub Milestones в инженерной платформе Sun Decor.
>
> Стандарт устанавливает назначение Milestones, требования к их использованию и место в инженерном процессе.
>
> Цель стандарта — обеспечить единообразное планирование и контроль достижения инженерных результатов.

---

# Purpose

Стандарт существует для определения единых правил использования GitHub Milestones.

Он позволяет:

- объединять связанные инженерные работы;
- планировать достижение результатов;
- отслеживать прогресс реализации;
- повысить прозрачность разработки;
- обеспечить предсказуемость поставки изменений.

---

# Scope

Настоящий стандарт распространяется на все GitHub Milestones организации Sun Decor.

---

# Milestone Concept

GitHub Milestone представляет собой инженерную цель (Engineering Delivery Goal).

Milestone объединяет набор связанных Issues, выполнение которых необходимо для достижения конкретного результата.

Milestone не является задачей и не заменяет GitHub Project.

---

# Usage Principles

GitHub Milestone используется для группировки инженерной работы по ожидаемому результату.

Milestone:

- объединяет взаимосвязанные Issues;
- отражает цель поставки изменений;
- не управляет состоянием задач;
- не используется для хранения документации;
- не заменяет Release.

---

# Milestone Rules

> [!important]
> Требования данного раздела являются обязательными.

## Rule 1 — Goal-Oriented Planning

Каждый Milestone должен представлять одну инженерную цель.

Не допускается объединение нескольких независимых целей в рамках одного Milestone.

---

## Rule 2 — Issue Association

Milestone объединяет только GitHub Issues.

Другие инженерные артефакты не включаются в Milestone напрямую.

---

## Rule 3 — Traceability

Каждый Milestone должен иметь понятное описание ожидаемого результата.

При необходимости допускается ссылка на связанную документацию, ADR или инженерные стандарты.

---

## Rule 4 — Project Independence

Milestone не определяет текущее состояние выполнения работы.

Управление состоянием осуществляется средствами GitHub Project.

---

## Rule 5 — Release Alignment

Если Milestone связан с выпуском продукта, он должен иметь связь с соответствующим Release.

---

## Rule 6 — Stable Goal

После начала реализации цель Milestone не должна изменяться без документированного обоснования.

---

# Recommendations

Рекомендуется:

- формулировать Milestone через ожидаемый результат;
- использовать краткие и понятные названия;
- включать только связанные между собой Issues;
- завершать Milestone после достижения заявленной цели;
- избегать чрезмерно крупных Milestones.

---

# Exceptions

Исключения допускаются только при наличии документированного архитектурного решения.

---

# Rationale

Milestone позволяет рассматривать разработку не как набор отдельных задач, а как достижение инженерных результатов.

Использование единых правил обеспечивает:

- прозрачность планирования;
- предсказуемость поставки изменений;
- улучшение навигации по инженерной работе;
- повышение управляемости разработки.

Milestone является связующим элементом между управлением работой (Project) и поставкой результата (Release).

---

# Compliance

Стандарт считается соблюдённым, если:

- Milestone описывает одну инженерную цель;
- в Milestone объединены только связанные Issues;
- цель сформулирована однозначно;
- управление состоянием осуществляется через GitHub Project;
- Milestone закрывается после достижения заявленного результата.
