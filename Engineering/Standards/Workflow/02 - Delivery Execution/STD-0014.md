# Pull Request Standard

> [!abstract]
> Настоящий стандарт определяет правила использования GitHub Pull Requests в инженерной платформе Sun Decor.
>
> Стандарт устанавливает назначение Pull Requests, требования к их созданию, проверке и интеграции изменений.
>
> Цель стандарта — обеспечить контролируемое внесение изменений, прослеживаемость реализации и единый процесс инженерной проверки.

---

# Purpose

Стандарт существует для определения единых правил использования GitHub Pull Requests.

Он позволяет:

- обеспечить контролируемую интеграцию изменений;
- организовать инженерную проверку результатов;
- сохранить историю реализации;
- повысить качество изменений;
- подготовить процесс к автоматизации.

---

# Scope

Настоящий стандарт распространяется на все Pull Requests организации Sun Decor.

---

# Pull Request Concept

Pull Request представляет собой инженерный артефакт, посредством которого предлагается интеграция завершённой работы в основную ветвь разработки.

Pull Request является связующим элементом между реализацией задачи и её включением в продукт.

---

# Usage Principles

Pull Request используется исключительно для интеграции инженерных изменений.

Pull Request:

- связан с одной или несколькими Issues;
- описывает завершённую работу;
- проходит инженерную проверку;
- фиксирует историю обсуждения реализации;
- не используется для постановки новых задач.

---

# Pull Request Rules

> [!important]
> Требования данного раздела являются обязательными.

## Rule 1 — Issue Traceability

Каждый Pull Request должен быть связан как минимум с одним GitHub Issue.

---

## Rule 2 — Single Logical Change

Pull Request должен содержать одну логически завершённую группу изменений.

Не допускается объединение нескольких независимых изменений без документированного обоснования.

---

## Rule 3 — Review Before Merge

Каждый Pull Request должен пройти инженерную проверку до объединения.

Проверка включает оценку соответствия требованиям, архитектурным решениям и инженерным стандартам.

---

## Rule 4 — Transparent Description

Pull Request должен содержать описание выполненной работы и ссылки на связанные инженерные артефакты.

При необходимости указываются:

- Issues;
- ADR;
- Standards;
- документация.

---

## Rule 5 — Merge as Completion

Объединение Pull Request означает завершение реализации соответствующего изменения.

Дальнейшее продвижение работы определяется Engineering Workflow.

---

## Rule 6 — Automation Support

При возможности Pull Request должен проходить автоматические проверки средствами GitHub Actions.

---

# Recommendations

Рекомендуется:

- создавать Pull Request небольшого размера;
- использовать понятные заголовки;
- избегать длительно существующих Pull Requests;
- связывать Pull Request со всеми затронутыми инженерными артефактами;
- устранять замечания до объединения.

---

# Exceptions

Исключения допускаются только при наличии документированного архитектурного решения.

---

# Rationale

Pull Request обеспечивает контролируемое внесение изменений в инженерную систему.

Использование единых правил позволяет:

- повысить качество реализации;
- обеспечить прослеживаемость изменений;
- сохранить историю инженерной проверки;
- подготовить процесс к автоматизированному контролю;
- снизить вероятность ошибок при интеграции.

Pull Request является обязательным этапом инженерного процесса между реализацией работы и её включением в продукт.

---

# Compliance

Стандарт считается соблюдённым, если:

- Pull Request связан с Issue;
- изменения представляют одну логически завершённую работу;
- выполнена инженерная проверка;
- описание содержит необходимый контекст;
- интеграция выполнена в соответствии с утверждённым процессом.
