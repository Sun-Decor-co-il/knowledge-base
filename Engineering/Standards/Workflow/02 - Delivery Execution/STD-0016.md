# GitHub Actions Standard

> [!abstract]
> Настоящий стандарт определяет правила использования GitHub Actions в инженерной платформе Sun Decor.
>
> Стандарт устанавливает назначение GitHub Actions, требования к автоматизации инженерных процессов и место автоматизации в жизненном цикле разработки.
>
> Цель стандарта — обеспечить единообразную, воспроизводимую и масштабируемую автоматизацию инженерной деятельности.

---

# Purpose

Стандарт существует для определения единых правил использования GitHub Actions.

Он позволяет:

- автоматизировать инженерные процессы;
- уменьшить количество ручных операций;
- повысить воспроизводимость процессов;
- обеспечить единообразное выполнение проверок;
- создать основу для развития инженерной платформы.

---

# Scope

Настоящий стандарт распространяется на все GitHub Actions, используемые в репозиториях организации Sun Decor.

---

# Automation Concept

GitHub Actions является основной платформой автоматизации инженерных процессов организации.

Автоматизация рассматривается как неотъемлемая часть Engineering Workflow.

GitHub Actions обеспечивает выполнение инженерных процессов без изменения их логики и правил.

---

# Usage Principles

GitHub Actions используется для автоматизации повторяемых инженерных операций.

Автоматизация:

- поддерживает существующие инженерные процессы;
- не заменяет инженерные решения;
- не изменяет требования стандартов;
- должна быть воспроизводимой;
- должна быть наблюдаемой.

---

# Automation Rules

> [!important]
> Требования данного раздела являются обязательными.

## Rule 1 — Standards Compliance

Автоматизация должна реализовывать требования инженерных стандартов, а не изменять их.

---

## Rule 2 — Workflow Integration

GitHub Actions должна быть интегрирована с утверждённым Engineering Workflow.

---

## Rule 3 — Repeatability

Автоматизированные процессы должны обеспечивать одинаковый результат при одинаковых входных данных.

---

## Rule 4 — Transparency

Результаты выполнения GitHub Actions должны быть доступны участникам инженерного процесса.

---

## Rule 5 — Incremental Automation

Автоматизация внедряется постепенно.

Ручной процесс должен существовать раньше автоматизированного.

---

## Rule 6 — Automation as Support

GitHub Actions является средством поддержки инженерной деятельности.

Ответственность за инженерные решения остаётся за участниками разработки.

---

# Recommendations

Рекомендуется:

- автоматизировать повторяющиеся операции;
- минимизировать ручные действия;
- использовать единые подходы к построению Workflow;
- регулярно пересматривать существующие процессы автоматизации;
- документировать назначение каждого Workflow.

---

# Exceptions

Исключения допускаются только при наличии документированного архитектурного решения.

---

# Rationale

Автоматизация позволяет обеспечить единообразное выполнение инженерных процессов.

Использование GitHub Actions позволяет:

- уменьшить влияние человеческого фактора;
- повысить воспроизводимость;
- ускорить выполнение типовых операций;
- обеспечить прозрачность инженерного процесса;
- подготовить инженерную платформу к дальнейшему развитию.

Автоматизация рассматривается как средство реализации инженерных стандартов, а не как самостоятельная цель.

---

# Compliance

Стандарт считается соблюдённым, если:

- автоматизация соответствует инженерным стандартам;
- результаты выполнения доступны участникам процесса;
- процессы воспроизводимы;
- автоматизация интегрирована с Engineering Workflow;
- ручной процесс определён до автоматизации.
