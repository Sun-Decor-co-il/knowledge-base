# Engineering Workflow

> [!abstract]
> Engineering Workflow определяет архитектурную модель жизненного цикла инженерной работы в организации Sun Decor.
>
> Документ описывает принципы построения инженерного процесса, последовательность инженерной деятельности, взаимодействие инженерных артефактов и общую модель прослеживаемости.
>
> Engineering Workflow является центральным архитектурным документом инженерной платформы Sun Decor и объединяет инженерную архитектуру, доменную модель, инженерные стандарты и средства автоматизации в единую систему.

---

# Purpose

Engineering Workflow существует для описания того, как инженерная работа возникает, развивается и завершается в организации Sun Decor.

В отличие от инженерных стандартов, определяющих правила использования отдельных инженерных артефактов, настоящий документ описывает полный жизненный цикл инженерной деятельности и взаимосвязь всех элементов инженерной платформы.

Engineering Workflow определяет архитектуру инженерного процесса независимо от используемых инструментов, продуктов и технологий.

Документ служит связующим звеном между инженерной архитектурой, доменной моделью, инженерными стандартами и средствами автоматизации, обеспечивая единое понимание процесса разработки для всех участников инженерной деятельности.

---

# Workflow Principles

Engineering Workflow строится на следующих архитектурных принципах.

---

## Engineering Before Tools

Инженерный процесс определяется архитектурой организации, а не возможностями используемых инструментов.

Конкретная инженерная платформа реализует Workflow, но не определяет его.

---

## Artifact-Driven Workflow

Каждый этап инженерной работы представлен отдельным инженерным артефактом.

Инженерные артефакты являются основными элементами Workflow и обеспечивают формализацию инженерной деятельности.

---

## Single Responsibility

Каждый инженерный артефакт обладает единственной областью ответственности.

Дублирование ответственности между инженерными артефактами не допускается.

---

## End-to-End Traceability

Engineering Workflow требует обеспечения непрерывной прослеживаемости инженерной работы на протяжении всего жизненного цикла.

Каждый инженерный артефакт должен сохранять связь с предыдущими и последующими этапами Workflow.

Любой опубликованный результат должен позволять восстановить цепочку инженерных решений от первоначального обсуждения до опубликованной версии продукта.

---

## Standardized Process

Все инженерные процессы реализуются в соответствии с утверждёнными инженерными стандартами.

Engineering Workflow объединяет инженерные стандарты в единую архитектурную модель процесса.

---

## Automation as Implementation

Автоматизация реализует требования инженерных стандартов, но не заменяет инженерные решения.

Workflow определяет процесс.

Инженерные стандарты определяют правила его выполнения.

Автоматизация обеспечивает реализацию этих правил средствами инженерной платформы.

---

## Continuous Evolution

Engineering Workflow рассматривается как развивающаяся архитектурная модель.

Изменение Workflow допускается только посредством документированных архитектурных решений.

---

# Workflow Overview

Engineering Workflow представляет собой архитектурную модель жизненного цикла инженерной работы.

Workflow начинается с момента формализации инженерной идеи и завершается публикацией инженерного результата.

Идея (Idea) сама по себе не является инженерным артефактом.

Первым формализованным инженерным артефактом Workflow является Discussion.

Основной поток инженерной работы выглядит следующим образом.

```text
Idea
        │
        ▼
Discussion
        │
        ▼
Issue
        │
        ▼
Pull Request
        │
        ▼
Release
```

Помимо основного потока Workflow использует поддерживающие инженерные компоненты.

```text
Project
        │
        └── manages ─────► Issue

Milestone
        │
        └── groups ──────► Issue

Label
        │
        └── classifies ──► Discussion
                           Issue
                           Pull Request

GitHub Actions
        │
        └── automates ───► Engineering Workflow
```

Основной поток описывает жизненный цикл инженерной работы.

Поддерживающие компоненты обеспечивают управление инженерной деятельностью, классификацию инженерных артефактов и автоматизацию инженерного процесса.

Таким образом, Engineering Workflow представляет собой не линейную последовательность инструментов, а единую архитектурную модель взаимодействия инженерных артефактов, инженерных стандартов и средств автоматизации.

Подробные правила использования отдельных инженерных артефактов определяются соответствующими инженерными стандартами.

---

# Workflow Phases

Engineering Workflow разделяется на четыре логические фазы.

Каждая фаза объединяет инженерные артефакты, выполняющие общую функцию в жизненном цикле инженерной работы.

Важно различать **Workflow Phases** и **Workflow States**.

Workflow Phases описывают логические области инженерной деятельности и отвечают на вопрос **«Что происходит?»**.

Workflow States описывают текущее состояние конкретной инженерной работы и отвечают на вопрос **«На каком этапе находится работа?»**.

Таким образом, фазы определяют архитектуру процесса, тогда как состояния отражают продвижение отдельной инженерной работы внутри этого процесса.

---

## Discovery

Discovery отвечает на вопрос:

> **Что необходимо сделать и почему?**

На данном этапе инженерная идея получает формализованное представление посредством инженерного обсуждения.

Основной инженерный артефакт:

- Discussion

Результатом фазы является принятое инженерное решение о начале или отказе от дальнейшей работы.

---

## Planning

Planning отвечает на вопрос:

> **Как будет организована инженерная работа?**

На данном этапе инженерная идея преобразуется в управляемую инженерную работу.

Основные инженерные артефакты:

- Issue
- Project
- Milestone
- Label

Результатом фазы является полностью подготовленная инженерная работа, готовая к реализации.

---

## Delivery

Delivery отвечает на вопрос:

> **Как изменение становится частью продукта?**

На данном этапе выполняется реализация инженерной работы, её инженерная проверка и интеграция изменений.

Основной инженерный артефакт:

- Pull Request

Результатом Delivery является инженерное изменение, готовое к публикации.

---

## Operations

Operations отвечает на вопрос:

> **Как инженерный результат поставляется и сопровождается?**

Фаза включает публикацию результата и выполнение автоматизированных инженерных процессов.

Основные инженерные артефакты:

- Release
- GitHub Actions

Результатом Operations является опубликованная версия продукта и завершённый жизненный цикл соответствующей инженерной работы.

# Workflow State Model

Engineering Workflow рассматривает инженерную работу как последовательность состояний.

Каждое состояние отражает текущую степень готовности инженерной работы независимо от используемой инженерной платформы.

```text
Idea
        │
        ▼
Discovery
        │
        ▼
Backlog
        │
        ▼
Ready
        │
        ▼
In Progress
        │
        ▼
Review
        │
        ▼
Done
        │
        ▼
Released
        │
        ▼
Archived
```

Описание состояний Workflow.

| State | Description |
|---------|-------------|
| Idea | Возникновение инженерной идеи до её формализации. |
| Discovery | Исследование, обсуждение и анализ инженерной идеи. |
| Backlog | Подготовленная инженерная работа ожидает планирования и приоритизации. |
| Ready | Инженерная работа полностью подготовлена к реализации. |
| In Progress | Инженерная работа находится в процессе выполнения. |
| Review | Выполненная инженерная работа проходит инженерную проверку. |
| Done | Работа завершена и принята, но ещё не опубликована. |
| Released | Результат опубликован и доступен пользователям. |
| Archived | Работа завершена и переведена в архивное состояние. |

Конкретная реализация модели состояний определяется конфигурацией Engineering Project организации Sun Decor.

---

# Workflow Transitions

Инженерная работа развивается посредством последовательных переходов между состояниями Workflow.

Переход представляет собой осознанное изменение состояния инженерной работы, подтверждающее завершение предыдущего этапа и начало следующего.

```text
State
        │
        ▼
Transition
        │
        ▼
State
```

Каждый переход должен удовлетворять следующим принципам.

- переход выполняется только после достижения цели текущего состояния;
- переход имеет документированное основание;
- переход должен быть прослеживаем;
- переход не должен нарушать последовательность жизненного цикла инженерной работы.

Engineering Workflow не допускает произвольного изменения состояния инженерной работы без соответствующего инженерного основания.

Конкретные условия выполнения переходов определяются инженерными стандартами и конфигурацией Engineering Project организации Sun Decor.
