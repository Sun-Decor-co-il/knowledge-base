# Engineering Document Identification Standard

> [!abstract]
> Настоящий стандарт определяет единые правила идентификации инженерных документов Knowledge Base организации Sun Decor.
>
> Стандарт устанавливает требования к структуре идентификаторов, правилам их присвоения, использованию префиксов и обеспечению уникальности документов.
>
> Цель стандарта — сделать инженерную документацию однозначно идентифицируемой, легко сопровождаемой и масштабируемой.

---

# Purpose

Стандарт существует для обеспечения единообразной системы идентификации инженерной документации.

Он позволяет:

- обеспечить уникальность документов;
- упростить навигацию по Knowledge Base;
- повысить прослеживаемость архитектурных решений;
- обеспечить масштабируемость инженерной документации;
- исключить неоднозначность при ссылках между документами.

---

# Scope

Настоящий стандарт распространяется на всю инженерную документацию, размещённую в репозитории Knowledge Base организации Sun Decor.

В частности, стандарт применяется к:

- Architecture Decision Records (ADR);
- инженерным документам (`ENG`);
- документам доменной модели (`GITHUB`);
- инженерным стандартам (`STD`);
- инженерным процессам (`PROC`);
- инженерным шаблонам (`TPL`);
- другим инженерным типам документов, утверждённым организацией.

Стандарт не распространяется на:

- пользовательскую документацию;
- маркетинговые материалы;
- юридические документы;
- документацию отдельных продуктов, если иное не определено отдельными стандартами.

---

# Rules

> [!important]
> Требования данного раздела являются обязательными.

## Rule 1 — Unique Identifier

Каждый инженерный документ обязан иметь уникальный идентификатор.

Идентификатор не может использоваться повторно даже после удаления документа.

---

## Rule 2 — Identifier Structure

Идентификатор состоит из двух частей.

```text
<PREFIX>-<NUMBER>
```

Пример:

```text
ADR-0001
STD-0007
ENG-0002
```

---

## Rule 3 — Prefix

Префикс определяет тип инженерного документа.

Префикс записывается латинскими буквами в верхнем регистре.

---

## Rule 4 — Sequential Numbering

Нумерация внутри каждого префикса является независимой.

Например:

```text
ADR-0001

STD-0001

ENG-0001
```

Это три различных документа.

---

## Rule 5 — Immutable Identifier

После публикации документа его идентификатор изменению не подлежит.

Переименование документа не влияет на его идентификатор.

---

## Rule 6 — Document Metadata

Идентификатор обязательно указывается в YAML Front Matter документа.

Пример:

```yaml
id: STD-0001
```

---

# Standard Prefixes

На текущий момент используются следующие префиксы.

| Prefix | Тип документа |
|---------|---------------|
| ADR | Architecture Decision Record |
| ENG | Engineering Document |
| GITHUB | GitHub Domain Model |
| STD | Engineering Standard |
| PROC | Engineering Process |
| TPL | Engineering Template |

Новые префиксы вводятся только после утверждения соответствующего архитектурного решения или стандарта.

---

# Recommendations

Рекомендуется:

- использовать четырёхзначную нумерацию (`0001`);
- сохранять непрерывную историю идентификаторов;
- не переиспользовать номера;
- указывать идентификатор в заголовке YAML каждого инженерного документа;
- использовать идентификаторы при ссылках на документы в ADR и стандартах.

---

# Exceptions

Исключения настоящим стандартом не предусмотрены.

Любое отклонение должно быть явно согласовано и документировано.

---

# Rationale

Идентификаторы являются фундаментом инженерной документации.

Они обеспечивают:

- стабильные ссылки между документами;
- прослеживаемость архитектурных решений;
- независимость идентификатора от названия документа;
- возможность безопасного переименования файлов;
- единообразие всей инженерной платформы.

Использование префиксов позволяет сразу определить тип документа, а независимая нумерация делает систему простой для сопровождения и расширения.

---

# Compliance

Стандарт считается соблюдённым, если:

- каждый инженерный документ имеет уникальный идентификатор;
- используется утверждённый префикс;
- номер соответствует последовательной нумерации внутри своего префикса;
- идентификатор указан в YAML Front Matter;
- идентификатор не изменялся после публикации документа.
