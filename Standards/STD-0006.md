# Repository Naming Standard

> [!abstract]
> Настоящий стандарт определяет единые правила именования репозиториев организации Sun Decor.
>
> Стандарт устанавливает требования к структуре имён репозиториев, соглашениям об именовании и принципам обеспечения единообразия.
>
> Цель стандарта — сделать структуру GitHub-организации предсказуемой, понятной и масштабируемой.

---

# Purpose

Стандарт существует для определения единых правил именования репозиториев.

Он позволяет:

- обеспечить единообразие GitHub-организации;
- повысить читаемость структуры организации;
- упростить поиск репозиториев;
- исключить неоднозначные имена;
- создать основу для автоматизации.

---

# Scope

Настоящий стандарт распространяется на все репозитории организации Sun Decor.

---

# Naming Principles

Имена репозиториев должны быть:

- короткими;
- понятными;
- однозначными;
- стабильными;
- отражающими назначение репозитория.

Имя репозитория является частью публичной инженерной архитектуры организации и должно рассматриваться как долгосрочное решение.

---

# Naming Rules

> [!important]
> Требования данного раздела являются обязательными.

## Rule 1 — Lowercase

Имя репозитория записывается только строчными латинскими буквами.

Пример:

```text
knowledge-base
landing-page
```

---

## Rule 2 — Word Separator

Для разделения слов используется символ дефиса (`-`).

Использование:

- пробелов;
- подчёркиваний (`_`);
- CamelCase;
- PascalCase

не допускается.

---

## Rule 3 — Meaningful Names

Название должно отражать назначение репозитория.

Не допускаются абстрактные или временные имена.

Например:

❌ `project`

❌ `repo1`

❌ `new-site`

✔ `landing-page`

✔ `knowledge-base`

✔ `crm-api`

---

## Rule 4 — Stable Naming

Имя репозитория не должно изменяться без объективной необходимости.

Переименование допускается только при существенном изменении назначения репозитория.

---

## Rule 5 — Consistency

Репозитории одного типа рекомендуется именовать по единым принципам.

Например:

```text
landing-page

knowledge-base

crm-api

crm-web

mobile-app
```

---

# Reserved Names

Следующие имена используются инфраструктурой GitHub и имеют специальное назначение.

Например:

```text
.github
```

Использование подобных имён допускается только в случаях, предусмотренных GitHub.

---

# Recommendations

Рекомендуется:

- использовать существительные;
- избегать сокращений без необходимости;
- избегать указания временных характеристик (`new`, `old`, `v2`);
- использовать дефис как единственный разделитель слов;
- сохранять имя репозитория неизменным на протяжении всего жизненного цикла.

---

# Exceptions

Исключения допускаются только при наличии документированного архитектурного решения.

---

# Rationale

Имя репозитория является одним из основных элементов инженерной навигации.

Последовательное именование:

- повышает читаемость GitHub-организации;
- облегчает поиск;
- снижает вероятность ошибок;
- способствует автоматизации инженерных процессов;
- упрощает сопровождение платформы.

Единые правила именования обеспечивают предсказуемость структуры организации независимо от количества продуктов и репозиториев.

---

# Compliance

Стандарт считается соблюдённым, если:

- имя соответствует установленным правилам;
- используются строчные латинские буквы;
- слова разделяются дефисом;
- название отражает назначение репозитория;
- отсутствуют необоснованные сокращения и временные обозначения.
